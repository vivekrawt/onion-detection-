# Flutter mobile client (Phase 7)

Install Flutter (3.22+ with Dart 3.4+, Android SDK and Java 17; use a current stable
Flutter release). Native runners are generated by the installed Flutter version:

```powershell
cd mobile
..\.venv-clip\Scripts\python.exe bootstrap.py
flutter pub get
flutter analyze
flutter test
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8001
```

Start the backend first. `10.0.2.2` means the host PC inside the Android emulator.
For a physical Android device, use your PC's LAN IP, start the backend with
`--host 0.0.0.0`, and allow port 8001 on your private network. HTTP is enabled
only in Android debug builds. For iOS use an HTTPS backend; native iOS builds
require macOS/Xcode. Camera and photo permission descriptions are set by bootstrap.
Release builds should use HTTPS. Do not use localhost for a backend on another device.

The six screens are in `lib/screens/`. `models/analysis_result.dart` parses the
backend response; `services/api_service.dart` uploads images and requests PDFs.
`main.dart` configures the application theme and entry screen. `bootstrap.py`
generates platform boilerplate without maintaining SDK-specific Gradle files by hand.

The download button opens the PDF in the device browser for saving. Sharing fetches
the actual PDF and invokes the device share sheet. Android lost-image recovery,
request errors, retry, and busy states are handled. Enable `ONION_DEBUG=1` on the
backend to view individual crops; all scores are available without debug mode.

No mobile build was run in the initial development environment because Flutter
was not installed. Check permissions, camera, uploads, PDF download/share, text
scaling, and real device networking before a demonstration.

Dependencies follow the official [image_picker](https://pub.dev/packages/image_picker/versions/1.1.2)
and [share_plus](https://pub.dev/packages/share_plus/versions/10.1.4) APIs.
